# lucernad: o daemon e o módulo de sistema — plano de implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIO: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para implementar este plano tarefa por tarefa. Os passos usam checkbox (`- [ ]`) para acompanhamento.

**Objetivo:** o binário `lucernad` com o módulo `system` (CPU, temperatura, memória, swap, rede, tempo ligado, máquina, discos e GPUs, sem nenhum processo externo, medindo só com assinante), o shell lendo dele por um cliente do protocolo genérico em QML, e o código antigo de medição fora do shell.

**Arquitetura:** três repositórios, nesta ordem. `lucerna-sdk`: só testes e documentação dos assinantes em tópicos comuns. `lucernad`: workspace Cargo com o crate de biblioteca `lucernad-system` (leituras puras de `/proc` e `/sys`, testadas com `testdata/`, o amostrador e o laço guiado pelos assinantes) e o crate `lucernad` (lib + bin no molde do `lucerna-hello`: serviço, linha de comando, manifesto e unidades). `lucerna-shell`: `services/lucerna/LucernaClient.qml` (o cliente do protocolo, genérico), `services/Lucernad.qml` (a conexão permanente) e `services/SystemStats.qml` como adaptador, com as mesmas propriedades de hoje.

**Tecnologia:** Rust 1.95 (edição 2024), `tokio` 1, `serde`/`serde_json` 1, `rustix` 1 (`statvfs`), `nvml-wrapper` 0.11 (NVML carregada em tempo de execução), o `lucerna-sdk` por git numa revisão fixa; QML do Quickshell 0.3 (`Quickshell.Io.Socket`); GitHub Actions; `gh api`.

**Spec:** `docs/superpowers/specs/2026-10-20-sistema-design.md` (neste repositório; leia inteiro antes da primeira tarefa). Base: `lucerna-sdk/docs/superpowers/specs/2026-10-19-protocolo-design.md`.

## Review Focus

1. **Montagem travada** (disco USB arrancado, FUSE local pendurado): o `statvfs` não volta. O esperado é o daemon seguir publicando `system.stats` e `system.gpus` no ritmo, o disco daquela montagem sumir da soma enquanto ela não responde e nenhuma thread nova ser pedida para a mesma montagem. Testes: `slow_statvfs_does_not_block` (Tarefa 3) e `stuck_disk_does_not_stop_stats` (Tarefa 5).
2. **O daemon reinicia com o shell aberto** (ociosidade, queda, atualização): o `seq` dos tópicos volta a `0`. O esperado é o shell aceitar os estados novos, não descartá-los como velhos para sempre. Teste: `lucernaclient: reconectar zera os seq vistos` (Tarefa 8).
3. **GPU dedicada suspensa:** com o `runtime_status` em `suspended`, nada que acorde a placa é lido: nem a NVML nem o `gpu_busy_percent`/hwmon da AMD. O esperado é a placa aparecer como suspensa, com `usage`/`temp`/`freq` `null`. Testes: `suspended_cards_are_not_read` (Tarefa 4) e a conferência na máquina real (Tarefa 7).
4. **Shell sobe antes do daemon, ou o daemon não existe:** o esperado é o shell mostrar "indisponível", tentar de novo com espera crescente (sem encher o log) e passar a mostrar os dados sozinho quando o daemon aparece, sem reiniciar o shell. Testes: `lucernaclient: conexão perdida falha os pedidos e agenda nova tentativa` (Tarefa 8) e a fase "lucernad fora" da fumaça (Tarefa 11).
5. **Dois clientes no mesmo tópico** (o shell e um `lucernad watch` no terminal): quando um sai, o outro continua recebendo; a amostragem só para quando os dois saem. Testes: `common_topic_counts_subscribers` (Tarefa 1) e `second_client_leaving_keeps_sampling` (Tarefa 5).

| Tema | Decisão | Por quê |
| --- | --- | --- |
| Crates | `crates/lucernad-system` (biblioteca: leituras, amostrador e laço do módulo) e `crates/lucernad` (lib + bin, no molde do `lucerna-hello`), com a feature `system` (padrão) ligando o primeiro | a lógica fica testável sem o binário; o próximo módulo vira outro crate e outra feature |
| Leitura do `/proc` e do `/sys` | código próprio, sem o crate `procfs` | são poucos arquivos, e o que importa é repetir as regras exatas do shell de hoje; menos dependências |

| NVML | `nvml-wrapper` (carrega `libnvidia-ml.so` em tempo de execução), atrás do trait `Nvidia`; `Nvml::init()` só com o `runtime_status` em `active`, uma leitura e `drop` (o handle fecha entre as leituras) | manter aberto só valeria com prova de que não impede a placa de dormir; a Tarefa 7 confere na máquina real que ela volta a dormir |
| AMD e Intel suspensas | também não são lidas (só fabricante, PCI, estado e nome) | ler o `gpu_busy_percent` do amdgpu acorda a placa; o spec pede não acordar a dedicada |

## Formato dos tópicos

Campos com os nomes do `SystemStats.qml`; números em JSON. O adaptador troca `null` por `NaN` em `cpuTemp`, `usage`, `temp`, `freq` e `maxFreq`.

```jsonc
// system.info — fixo, lido ao subir
{"cpuModel":"Intel(R) Core(TM) i7-1165G7","cpuThreads":8,"hostname":"maquina","osName":"Arch Linux","kernel":"6.17.2-arch1-1"}

// system.stats — null até a primeira amostra
{"cpuUsage":0.23,"cpuTemp":48.0,"memTotal":16384000000,"memUsed":10240000000,"swapTotal":2048000000,"swapUsed":0,
 "rxRate":1532.5,"txRate":220.0,"rxTotal":123456789,"txTotal":2345678,"rxHistory":[0.0,1532.5],"txHistory":[0.0,220.0],"uptime":12345.67}

// system.disks — null até a primeira amostra; o da raiz primeiro
{"disks":[{"name":"nvme0n1","size":2400,"used":540,"root":true},{"name":"sda","size":1000,"used":400,"root":false}]}

// system.gpus — null até a primeira amostra; na ordem dos card*
{"gpus":[{"card":"card0","vendor":"intel","pci":"0000:00:02.0","state":"active","name":"Intel (integrada)","usage":null,"temp":null,"freq":1450,"maxFreq":1500}]}

// system.status
{"available":true,"error":null}
```

- `cpuUsage` e `usage`: 0 a 1 (`f64`). `cpuTemp`: °C (`f64`) ou `null` sem sensor. `mem*`, `swap*`, `rxTotal`, `txTotal`, `size`, `used`: bytes (inteiros). `rxRate`, `txRate`: bytes/s (`f64`, ≥ 0). `rxHistory`, `txHistory`: até 30 taxas, a mais velha primeiro. `uptime`: segundos (`f64`).
- `vendor`: `"nvidia"`, `"amd"` ou `"intel"`. `state`: `"active"` ou `"suspended"`. `name`: o `Model:` de `/proc/driver/nvidia/gpus/<pci>/information` (NVIDIA) ou o genérico (`"NVIDIA"`, `"AMD Radeon"`, `"Intel (integrada)"`). `temp`: °C (`f64`; AMD: `temp1_input / 1000` truncado para inteiro; NVIDIA: o inteiro da NVML) ou `null`. `freq`, `maxFreq`: MHz inteiros ou `null`.

```rust
#[tokio::test]
async fn common_topic_counts_subscribers() {
    let mut b = demo();
    let seen = b.topic("seen", json!({"n": 0}));
    let (_t, p, _s) = start(b).await;
    assert_eq!(seen.subscribers(), 0);

    let mut a = ready(&p).await;
    a.send(&req(1, "lucerna.subscribe", json!({"topics":["seen"]}))).await.unwrap();
    assert_eq!(next(&mut a).await["result"]["states"][0]["topic"], "seen");
    // A guarda é contada antes da resposta: já vale aqui, sem esperar.
    assert_eq!(seen.subscribers(), 1);
    tokio::time::timeout(Duration::from_secs(1), seen.wait_subscribed()).await.unwrap();

    a.send(&req(2, "lucerna.subscribe", json!({"topics":["seen"]}))).await.unwrap();
    next(&mut a).await;
    assert_eq!(seen.subscribers(), 1, "reassinar na mesma conexão não conta de novo");

    let mut b2 = ready(&p).await;
    b2.send(&req(1, "lucerna.subscribe", json!({"topics":["seen"]}))).await.unwrap();
    next(&mut b2).await;
    assert_eq!(seen.subscribers(), 2, "duas conexões, dois assinantes");

    a.send(&req(3, "lucerna.unsubscribe", json!({"topics":["seen"]}))).await.unwrap();
    assert_eq!(next(&mut a).await["result"], json!({}));
    assert_eq!(seen.subscribers(), 1, "quem saiu não segura o outro");

    drop(b2);
    tokio::time::timeout(Duration::from_secs(1), seen.wait_unsubscribed())
        .await
        .expect("fechar a conexão devolve o assinante");
    assert_eq!(seen.subscribers(), 0);
}

O laço (o único algoritmo que as assinaturas não determinam):

```
loop {
    espera o primeiro assinante de stats, disks ou gpus (select! dos três wait_subscribed)
    ticker = interval(intervalo atual), MissedTickBehavior::Skip   // o primeiro tick é já
    loop {
        select! { ticker.tick() => {}, intervalo mudou => { sampler.set_interval(novo); ticker = interval(novo); continue } }
        want = Groups { stats: stats.subscribers() > 0, disks: …, gpus: … }
        sampler.reset(!want)                           // grupo sem assinante esquece a linha de base
        se nenhum: break                               // volta a esperar
        want.stats → stats.publish(Stats)              // sempre
        want.disks → {"disks": …} se mudou desde o retrato atual
        want.gpus  → {"gpus": …}  se mudou
    }
}

O `Sampler`: CPU e rede guardam a leitura anterior (rede com o `Instant`); sem anterior (início de ciclo), repete o `cpu_usage`/`rx_rate`/`tx_rate` da última `Stats` e não põe ponto no histórico; com anterior, calcula e põe (`push_history`). O sensor de temperatura é escolhido (`find_sensor`) no início de cada ciclo de `stats`.
