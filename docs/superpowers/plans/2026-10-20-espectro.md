# lucernad: o módulo de espectro — plano de implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIO: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para implementar este plano tarefa por tarefa. Os passos usam checkbox (`- [ ]`) para acompanhamento.

**Objetivo:** o módulo `spectrum` do `lucernad` (captura do PipeWire só do player exibido, FFT própria, 48 bandas suavizadas a 60 quadros por segundo, só com assinante e com player) e o shell lendo dele pelo cliente do protocolo, com o `cava` e as ondas pelo nível do som fora.

**Arquitetura:** dois repositórios. `lucernad`: o crate novo `lucernad-spectrum` (o backend do PipeWire atrás do trait `Backend`, a análise como função pura, o casamento player → nó sobre `/proc` e D-Bus atrás de traits, e o laço guiado pelo assinante e pelo player), o crate novo `lucernad-core` (o `detached` e o `ModuleTask`, que saem do `lucernad-system`) e a feature `spectrum` (padrão) no binário. `lucerna-shell`: o `LucernaClient` passa a somar os tópicos de vários donos, o `Spectrum.qml` vira adaptador do `spectrum.bands`, e o anel perde as ondas. O `lucerna-sdk` não muda.

**Tecnologia:** Rust 1.95 (edição 2024), `pipewire` 0.10 (0.10.1, com `libspa` 0.10.1), `zbus` 5 (5.19, só o runtime do tokio), `rustfft` 6 (6.4.1), `tokio` 1, `serde_json` 1, o `lucerna-sdk` na revisão de hoje; QML do Quickshell 0.3.2 (`MprisPlayer.dbusName`); PipeWire 1.6 e WirePlumber 0.5 na máquina; GitHub Actions; `gh`.

**Spec:** `docs/superpowers/specs/2026-10-20-espectro-design.md` (neste repositório, na `main` desde o db58a23, PR #7; leia inteiro antes da primeira tarefa). Base: `docs/superpowers/specs/2026-10-20-sistema-design.md` e o plano `docs/superpowers/plans/2026-10-20-sistema.md`, cujos padrões este plano segue.

## Review Focus

1. **Player pausado com o nó ainda aberto** (o Spotify pausa e o nó fica; o Chromium suspende o fluxo): o anel desce a zero pela queda suave, em vez de congelar no último quadro. Testes: `stale_ring_counts_silence` (Tarefa 2) e `silent_node_falls_to_zero` (Tarefa 4).
2. **O nó do player some com a captura aberta** (app fechado, aba mutada): o fluxo do `lucernad` nunca cai no microfone nem no padrão do WirePlumber. Teste: `capture_never_falls_back_to_the_microphone` (Tarefa 1, no PipeWire isolado) e o passo 5 da conferência (Tarefa 6).
3. **Player que reinicia com o mesmo nome D-Bus** (Spotify fechado e aberto: PID novo): o anel volta a seguir sem novo `spectrum.configure`. Teste: `restarted_player_is_found_again` (Tarefa 4).
4. **O info do client chega depois do nó** (o registro anuncia o nó antes de o client ter `application.process.id`): a captura começa quando o info chega. Testes: `node_without_client_info_never_matches` (Tarefa 3) e `client_info_arriving_later_starts_capture` (Tarefa 4).
5. **O PipeWire reinicia ou cai no meio** (`systemctl --user restart pipewire`): vira estado, o módulo tenta de novo e volta sozinho, sem pânico nem laço travado. Teste: `pipewire_drop_becomes_state_and_retries` (Tarefa 4) e o passo 6 da conferência (Tarefa 6).

## Formato

```jsonc
// spectrum.bands — tópico contínuo; null até o primeiro quadro
{"bands":[0.0,0.125,0.5,1.0, … 48 números de 0 a 1, com até 3 casas]}

// spectrum.status — tópico comum
{"available":true,"capturing":false,"player":"org.mpris.MediaPlayer2.spotify","error":null}
```

- `spectrum.configure {"player": "org.mpris.MediaPlayer2.<…>" | null}` → `{}`. Outro valor (número, nome sem o prefixo, chave faltando) → `-32602` com `RpcError::invalid_params("player precisa ser um nome org.mpris.MediaPlayer2.* ou null")`. Vale o último pedido.
- `available`: a última conexão (ou a sonda) deu certo. `capturing`: sessão aberta com pelo menos um nó casado. `player`: o configurado. `error`: o último erro, `null` depois de uma conexão boa.

```
                                      // com Connection::session() dentro do mesmo prazo (dbus_timeout)
    analyzer = None; rings; nodes = []; casados = []
    tick = interval(FRAME), Skip; reid = interval(REIDENTIFY), Skip
    loop { select! {
        tick → se há analyzer: quadro = analyzer.frame(rings.window(agora)), arredondado a 3 casas;
               publica {bands} se ≠ o último publicado
        reid.tick(), só com casados vazio → identity = identify(player); recasa(nodes)
        evento →
            Graph(n)   → nodes = n; recasa(nodes)
            Samples    → se serial ∈ casados: rings.push; analyzer = Analyzer::new(rate) se não há ou a taxa mudou
            Disconnected(_) | None → status {available:false, capturing:false, error:"O PipeWire fechou a conexão."};
                         sai e espera retry
        player.changed() → None: sai; Some(novo): identity = identify(novo); rings.clear(); analyzer = None;
                           recasa(nodes); status player
        bands.wait_unsubscribed() → sai
    } }
    drop(sessão); publica 48 zeros se o último publicado não era de zeros; status capturing false
}

recasa(nodes): casados = detached(match_nodes(identity, nodes, ProcFs), PROC_TIMEOUT) (prazo: mantém o anterior);
               control.capture(casados); rings.retain(casados); status capturing = !casados.is_empty()
```

O `identify` dentro de um braço do `select!` segura os outros braços por até `dbus_timeout` (1 s): aceitável, porque só acontece na abertura, na troca de player e uma vez por segundo com o casamento vazio (sem captura, não há quadro a atrasar).
